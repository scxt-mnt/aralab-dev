# Changelog

All notable changes to AraLab, newest first. Entries before v77 are kept as originally written.

## Test mode (v55)
Double-click **START-TEST.bat**. It runs the app locally in **test mode**: you are already signed in as a sample student, all data is sample data kept in the browser, and **Supabase is never contacted** (server features such as AI generation and email are switched off). Works only with `npm run dev`; a production build ignores it. On a phone on the same Wi-Fi, open the *Network* address printed in the window. In the browser console, `__testNotify("Hello")` sends a live test notification.

- **v74**: **AraLab can now listen to a video and write the transcript itself.** On Google Classroom, a lesson that has a Drive video or audio file gets **Transcribe the video** (in the lesson box and in the transcript dialog). The browser reads the audio, mixes it to mono at 16 kHz, and sends it to our AI in **90-second pieces** (each piece is a small WAV, so long lectures are not one giant request); the pieces are written down in order and joined. Pressing **Generate** on a video lesson does this automatically when no transcript exists yet, then builds the reviewer from the words. The result lands in the same transcript slot as a paste: cleaned, measured, saved in this browser, reused on every later build. Limits, because the decoding happens on the student’s device: 30 minutes (10 on phones) and 250 MB — longer videos, and **YouTube links** (we never get their audio), still use the paste dialog, which stays one tap away. If the audio cannot be decoded, the build falls back to the slide pictures instead of failing. New route `POST /api/transcribe` (signed-in only, ~3 MB of audio per request, Gemini first and **Groq Whisper** as the backup — optional `GROQ_WHISPER_MODEL` to pick the speech model), pure helpers in `src/transcribe.js`, prompt/limits in `server/transcribe.js`. Audio is never retried on Groq's text models, so the backup can never invent words. No SQL changes, no new required env vars.

One dialog does the work: paste from YouTube's **Show transcript** (or Meet captions, or the teacher's notes) and AraLab **cleans it on paste** — leading and inline `0:12` / `1:02:03` timestamps, bare timestamp lines, HTML entities and repeated caption lines are removed — then shows a live **word count and minutes** estimate. **Save & generate** stores the transcript and builds the reviewer in one tap; **Save** keeps it for later and **Remove** deletes it. The transcript is kept in this browser (`rl-gc-tr:<user>`, 30 lessons, 60k characters each) so a long transcript survives a reload, and every Generate/batch build picks it up with no extra step. A lesson with only a video can now be generated; one with neither files nor a usable transcript says exactly what to do. Pure helpers `cleanTranscript()` / `transcriptInfo()` live in `src/classroomLogic.js`. No SQL changes.

## v57: the AI switches models when an answer is broken
Before, a model that returned invalid JSON, an empty reviewer, a cut-off answer, or a 400 error failed the whole request and the student had to press Retry.
Now `generateJson({ validate })` checks every answer. If it is unusable, that model is skipped and the NEXT model is tried automatically (up to 8 models, then a second round). Only if every model fails does the student see an error, and it states the real reason.
Used by: generateFlow (reviewer), screen (AI check), fixFlow (fix from feedback). Tests: tests/unit/geminiRace.test.mjs.

## v60: student IDs generate again
**Cause:** `profiles_guard()` is defined three times in `supabase-setup.sql`. The first two gave each new profile an ID (like `S26-000123`); the last one (the ban-field guard) did not, so every account created after it got **no ID**.
**Fix:** the ID now has its own trigger (`profiles_student_no_trg`), so changing a guard later can never switch it off again. It assigns an ID on insert, never changes an existing one, and ignores a value typed in by a client. The counter is moved past the highest ID already used, and every student without an ID gets one.
**To apply:** run **`fix-student-id.sql`** once in Supabase > SQL Editor (or re-run the whole `supabase-setup.sql`). Safe to run more than once. A test (tests/unit/studentId.test.mjs) fails if a later guard ever comes after the ID trigger by mistake.

## v61: video lessons in Google Classroom
Videos attached from **Google Drive** (MP4, WebM, MOV) can now become reviewers. YouTube links still can't be read.
How: the browser downloads the video, plays it silently, and looks at a tiny grey picture every ~3 s (12 to 240 looks). A frame is kept only when it differs enough from the last kept one (a new slide / diagram / page; `SCENE_THRESHOLD` in `src/videoFrames.js`). If there are more changes than fit, the biggest changes win. The kept frames (max 16) are tiled 2x2 into up to 4 JPEG contact sheets with the time in each corner, and go through the normal upload + AI check + generate flow as images. So there is no server, database or storage change.
Limits: video up to 300 MB (the browser downloads all of it), up to 3 hours; a video uses up to 4 picture sheets of a request. Since v71 there is no image count limit; the 40 MB total per request is the cap. Writing a video down (v74) is separate: up to 30 minutes / 250 MB on a computer (10 minutes on a phone), because the audio is decoded on the device.
Honest limit: **only the pictures are read, not the sound.** Good for slide-based lectures, screen recordings and whiteboards; a talking-only video gives little. The AI is told this and not to guess what was said.
Code: `src/videoFrames.js` (pure, tested), `src/videoToSheets.js` (browser), `selectFiles` in `src/classroomLogic.js`, a note for the AI in `server/aiFiles.js`.

The shortcut for the screen you are already on is left out.
- On the **Create** screen the first shortcut becomes **How to create a reviewer**, which opens the guide straight on the "Where do I create a reviewer?" step.
- Until a student opens it once, the button reads **+ Quick start** and pulses softly (5 times) so it gets noticed; after that it is a small round button. Stored in `localStorage` key `rl-dial-seen`. Esc, the dimmed background, choosing a shortcut, or changing screen closes it; Arrow keys move between shortcuts. It hides while the phone keyboard is open, sits below the reader, Challenge, dialogs and toasts, and is not printed.
- The **Welcome guide** now accepts a `start` step, and its wording was corrected: Create reviewer is under **Library > Create** (not a bottom-bar tab), there is no approval step any more, and Astra members monitor generation and remove reviewers instead of approving requests.
- Code: `src/SpeedDial.jsx`, `src/speedDialLogic.js` (items, tested in `tests/unit/speedDial.test.mjs`), styles at the end of `src/styles.css`, wiring in `src/App.jsx` (`openGuide`, `dialGo`). To add or change a shortcut, edit `DIAL_ITEMS` in `speedDialLogic.js` only. No SQL changes, no new packages.
